# The docs: the menu as the drone's manual

*Agreed 2026-10-22, in chat. The plan is in [plans/2026-10-22-the-docs.md](../plans/2026-10-22-the-docs.md).*

## What I asked for

Go over every page in the menu: consolidate what repeats, clean it up, verify it, and organize it. The menu is the drone's documentation, so it should be in depth and technical, and anything the drone view shows (Inside it, Fly it) should be in it too.

## What was wrong

An audit of all ten pages found:

- **Numbers shown as current that aren't.** Every step printed each step's outcome as the README plan had it at the time. Max "passing at 2254 g" now fails at 2620 g, and the step 8 prices disagree with Build it's. The spec sheet rounded its own way (22.3 where the report says 22.2), called the speed for the longest flight "farthest per charge", and listed parts that didn't add up to the weight.
- **The same thing in three places.** Parts on the spec sheet, Build it and the catalog. Reports through Every step, the library and the data. What it can't prove listed the chute's opening time three times.
- **The drone view knowing more than the docs.** Each scenario's one-liner and drawing, the event captions in plain words, the wind tunnel's seven cases and forces, each pin's source, how hard each route's wires work. And the wiring pages weren't in the menu.
- **No order.** Combinations in a different order on each page, the catalog's catch-all second, the library oldest first with nothing marked superseded, links going out to GitHub when the doc is right there.

## What it becomes

One home for each subject, grouped like a manual. Each page carries its subject in depth, and the others link to it instead of repeating it.

| Group | Page | Holds |
|---|---|---|
| The drone | Overview | What it is, the modules, the eight combinations with weight, hover and verdict, where each step stands, how to read these docs |
| | Spec sheet | Each combination's numbers, exactly as the reports print them, every check with its target and note, the mass breakdown that sums, balance, the pack and power |
| | Parts | Everything on the drone by module (mass, price, link, checked date, notes, fallback), hardware and printed parts, then the catalog's alternatives, each with its full record |
| | Wiring | Every board's pins, the harnesses, the wire list with cut lengths, and where each pin's position comes from |
| Tested | Flights | Each scenario with its one-liner and drawing, grouped by step, a legend, and why each run failed; each run's page with plain captions |
| | Wind tunnel | The seven cases under one set of names, the forces, how it was run, the stills beside their case |
| | What it can't prove | Each item once, grouped by step, with STATUS's open items |
| The work | Steps | Each step's status and its key numbers as its report has them now |
| | Build it | The costs, the guides, the test plans; the parts are on Parts |
| Reference | Library | Newest first, each topic's spec, plan and log together, superseded docs marked |
| | Data | Each file with its title, what it holds and its size, the site's own data too |
| | The math | The math, in step order, documented functions first, links pinned to the commit |

Everywhere:

- One order for the combinations: base, V, P, C, mission, V+C, P+C, max.
- One spelling of each name.
- Links stay inside the site wherever the doc is in the library.
- A number on a page comes from its report's data, formatted the way the report formats it, and a test checks that.

## Not in this

- New analysis. The pages show what the reports and the design already hold. The aero numbers still wait for OpenFOAM.
- The drone view itself, except where its information moves into the docs as well.
