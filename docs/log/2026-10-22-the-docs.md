# 2026-10-22: The menu becomes the manual

*2026-10-22, on the PC. The [spec](../specs/2026-10-22-the-docs.md) and the [plan](../plans/2026-10-22-the-docs.md).*

The project site has two faces. The drone view is the fun one: one 3D drone, Inside it with every wire drawn over a blueprint, and Fly it, where every recorded run plays as a loop. Behind a small menu in the corner sat everything else, and by now that was a lot of text: ten pages that had grown one step at a time. I asked for all of it to be gone over. Not trimmed, since this is the drone's documentation and should be in depth and technical, but cleaned up, checked and put in order. And anything the drone view shows should be in the docs too.

## What was wrong

I went through all ten pages first, and it was worse than messy in places. It was wrong.

The worst kind was old numbers shown as if they were current. The page per step printed each step's outcome the way the README's plan had it when the step finished. Step 1 still said every setup passed with Max at 2254 g. Max has since grown to 2620 g and misses its own 2500 g target. Step 8's prices disagreed with Build it's. The spec sheet rounded its own way, 22.3 min where the sizing report says 22.2 (the report always rounds toward failing), and listed parts that didn't add up to the weight next to them.

Then the same thing in three places: the parts on the spec sheet, on Build it and in the catalog, and the reports reachable from the step pages, the library and the data. Then the drone view knowing more than the docs did. Each scenario's one-line description and drawing, the flight events in plain words, the wind tunnel's seven cases and their forces, where each wire's pin position came from: all of it lived only in the 3D view. The wiring pages weren't even in the menu. And no order: the module combinations came in a different order on each page, the library ran oldest first with nothing marked as replaced, and half the links went out to GitHub when the same doc was right there on the site.

## What it is now

Twelve pages in four groups, like a manual, with one home for each subject. The other pages link to it instead of repeating it.

| Group | Pages |
|---|---|
| The drone | Overview, Spec sheet, Parts, Wiring |
| Tested | Flights, The wind tunnel, What the sims can't prove |
| The work | Every step, Build it |
| Reference | Library, Data, The math |

A few rules hold across all of them. The combinations always come in one order: base, V, P, C, mission, V+C, P+C, max. A number on a page comes from its report's data, formatted the way the report formats it, and a test checks the page against the report. Links stay on the site wherever the doc is in the library.

I did it in six passes, each tested, checked in the browser and committed before the next.

**The drone.** A new overview: what the drone is, the modules, the eight combinations with their weight, hover and verdict, where each step stands, and how to read the docs. The spec sheet now prints every number exactly as the sizing report does, with each check's target and note, and the weight broken down line by line so it adds up. Parts replaces three lists: everything on the drone by module, each line with its note, its fallback and its whole catalog record, then the alternatives. Wiring joined the menu, with every wire, each plug's pin source and how hard each route's wires work.

**What was tested.** Flights got a pass matrix per step with its own count, what each scenario tests with the same drawing Fly it uses, and why each of the 28 misses missed. The flight pages say each event in plain words. The wind tunnel page has its seven cases in one table, under the same names as the drone view, with each one's tunnel size, grid, seconds of air and force. What the sims can't prove lists each item once, under its step.

**The work.** Each step's page now shows its report as it stands today, in the report's own words: its verdict, its key numbers and its sections, each a link into the report. Below that is the outcome I wrote in the plan when the step finished, labeled as exactly that. So step 1 still says what I found on 2026-10-17, and right above it the report says Max misses its weight target today. A test holds every key number to its report. Every log post has its step now (some had been quietly filed under planning), and the side tracks say what they're for.

**Reference.** The library goes by topic: each step's spec, plan and log posts together, the newest topic first. Four docs that later ones replaced, in part or whole, say so in their own first lines now, and the library marks them. The data page lists every report's data file and every file the site itself reads, with what each holds and its size. The math page is only the code that does the math, in step order, with the functions that explain themselves first and the links pinned to the commit the site was built from, so the line numbers don't drift.

## What broke, and what I found on the way

The site's checks on GitHub had been failing since 2026-10-21, and I hadn't noticed. One test, for the HaLow radio link in the sim, fired 2000 packets at the ground station's listener all at once, before the listener got a chance to read any. The computer's own network buffer filled and dropped most of them, so the test saw 221 of 2000 arrive here and 1093 on GitHub, and failed, without the link model doing anything wrong. It sends them in batches now and passes every time. That's a lesson I'll take: a red mark that's been red for a day stops being noticed.

The numbers check found more than I expected. Self-tuning's worst miss is 0.305%, which my first version rounded up to 0.4% while the report says 0.3%. The status file still had Max at 2623 g (it's 2620) and the old prices. Cleaning out a picture the old home page used, I deleted the list of build guides along with it by accident, and the lint caught it before anything ran.

Two pages' data turned out to be read by nothing: the full catalog file and the old home page's picture. They're gone, and the site's first load is 350 kB of its 600 kB budget.

## After my first look

Clicking Menu every time I wanted another page got old fast, so the contents stay on screen now. On any docs page the twelve pages run down the left side, pinned while the page scrolls, with the one I'm on marked in spearmint. On a phone there's no room for both, so the menu button stays there. Under the page I'm on, its sections are listed too, read from the page's own headings, so a long page is one click from any part of it, and the one I'm reading lights up as I scroll.

The costs had every part's price and no plain total. Build it now says it in one line: one drone from nothing, with the transmitter, charger, tools and spares, is $1,238.77 for Base and $2,534.28 for Max, and its table has that all-in figure for each combination. Parts shows each line's total, each module's, and the whole drone's at the top. The screws and printed parts still aren't in the sums: they're cheap, and the printed ones are filament.
